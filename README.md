# iiv-server

Windows 10 / 11 用のリモート デスクトップのサーバーです。この PC の画面を、ほかの PC の
[iiv-client](https://github.com/iosxi/iiv-client) から見たり操作したりできるようにします。

[iivnc-server](https://github.com/iosxi/iivnc-server)(VNC のサーバー)の後継で、**VNC の規格を捨てて**、
画面を GPU の動画エンコーダ(H.264)で送ります。VNC のビューアからはつながりません。

- **速く、軽い。** 4K の画面を 60 フレーム/秒で送って、サーバーの CPU は 2〜5%、帯域は数 Mbps(下の「測った結果」)。
- **インストール不要。** `iiv-server.exe` を好きな場所に置いて起動するだけ。ランタイムも DLL も要りません。
  H.264 の符号化には、Windows に最初からある Media Foundation を使います。
- **レジストリを使わない。** 設定は exe と同じ場所の `iiv-server.ini`(UTF-8 のテキスト)だけ。

**v1 は最初の版です。** 下の「できないこと・確かめていないこと」も読んでください。

## 使い方

1. `iiv-server.exe` を起動します。最初は設定画面が開くので、**パスワード**(64 文字まで)を入れて OK。
   以後は通知領域(タスクトレイ)に常駐し、ポート **5960** で待ち受けます。
2. 初めて待ち受けるときに Windows Defender ファイアウォールの確認が出ます。使うネットワークにチェックを入れて許可してください。
3. 相手の PC で iiv-client を起動し、この PC のアドレス(設定画面の「状態」に出ます)を入れて接続します。

トレイのアイコンは、誰かが接続している間は緑になります。トレイのアイコンをクリックすると設定画面、
右クリックで「全員を切断」「終了」。設定画面の項目・サービス(ログイン前から使う)・ネットワークの許可・
カーソルの扱いは iivnc-server と同じです(iivnc-server の README を参照。ポートの既定だけ 5960)。

**通信は暗号化していません。** パスワードは回線を通りません(下の「仕組み」)が、画面とキー入力はそのまま流れます。
家や職場の LAN の中で使ってください。インターネット越しに使うときは VPN の中で。

## 仕組み(速さのための工夫)

- **絵を GPU から降ろさない。** DXGI の Desktop Duplication で取り込んだ画面を GPU の上で 1 枚にまとめ、
  D3D11 の VideoProcessor で NV12(BT.709)に変え、GPU のエンコーダ(NVIDIA / Intel / AMD のハードウェア MFT)へ
  テクスチャのまま渡します。CPU は絵に触りません。GPU のエンコーダが無い PC では Windows 標準の CPU のエンコーダを使います
  (1920×1080 まで縮めて)。
- **押し出し式。** 画面が変わったら、相手に求められなくても送ります。相手は表示したフレームの番号を返し、
  返事の無いフレームが 2 つを超えたら次を待ちます(その間の変化は次のフレームにまとまるので、遅れが溜まりません)。
  返事を返さない相手がいても、ほかの相手は止まりません。
- **動いている間は軽く、止まったらくっきり。** ビットレートを一定にせず、画質で決めます(動いている間は画質 70)。
  変化が 150ms 止まったら、同じ絵を画質 95 でもう 1 枚送ります。止まった所はその後も参照として使われるので、
  くっきりしたまま残ります。止まった画面ではほとんど何も送りません。
- **新しい相手が来たらキーフレーム。** それ以外はキーフレームを送りません(帯域の山を作らない)。
- **パスワードは回線を通らない。** ini には PBKDF2-SHA256(10 万回)で導いた鍵だけを置き、接続のたびに乱数の
  問いに HMAC-SHA256 で答えてもらいます(Windows 標準の BCrypt)。

## 測った結果(2026-10-06。Core i7-12700KF・RTX 3070 Ti・Windows 11・4K 60Hz 1 枚。同じ PC の中の折り返し)

**実画面(4K)。** 1280×720 の窓が 60fps で動く(`tools/realbench.py`。窓は iivnc の `srcwin.py`)。
遅れは、フレームに付いてくる「画面に出た時刻」(DXGI)から受け手が受け取るまで。

| 絵 | iiv v1 | iivnc-server v8(参考) |
|---|---|---|
| ふだんの操作(文字が流れ、四角が動く) | 60 フレーム/秒・2.1Mbps・CPU 4.5% | 57 フレーム/秒・128Mbps・CPU 49% |
| 動画(窓の全面が毎フレーム変わる) | 60 フレーム/秒・4〜7Mbps・CPU 3% | 57 フレーム/秒・193Mbps・CPU 54% |
| 遅れ(中央値) | 12〜13ms | 7〜8ms |

遅れが iivnc より数 ms 大きいのは、4K の H.264 の符号化に 1 回 約 9ms かかるため(1920×1080 なら 2.5ms)。
「速さ優先」(`CODECAPI_AVEncCommonQualityVsSpeed` = 0)で 11.4 → 9.2ms にしてある。

**iiv-client と組み合わせて(合成した 1920×1080 の、全面が毎フレーム変わる絵)。**
iiv-client v1 の `tools/pairbench.py`。クライアントは GPU で復号(DXVA)。

| | iiv v1 | iivnc v8 + iivnc-client v10(参考) |
|---|---|---|
| フレーム/秒 | 60(画面の書き換えの速さで頭打ち) | 103〜118 |
| 帯域 | 21Mbps | 710〜830Mbps |
| クライアントの CPU(1 フレームあたり) | 1.9ms | 12〜14ms |

## できないこと・確かめていないこと

- **色の付いた細かい文字の縁が少しにじみます。** H.264 は色の情報を縦横半分(4:2:0)で送るため。
  明るさは元の絵とよく合います(止まった検証用の絵で PSNR 46dB、文字の欄で 41dB)が、ClearType の色付きの縁は崩れます。
  次の版で、止まった所を劣化なしで上書きする予定です。
- 4K を超える画面(合計の幅が 4096 を超える複数の画面など)は、H.264 の上限(4096×2304)に収まるよう縮めて送ります。
- 画面が複数の GPU につながっているときは、最初の GPU の画面だけを送ります。回転した画面があるときは GDI で取り込みます。
- 確かめていないこと: **Windows 10 の機械**、Intel / AMD の GPU、GPU のエンコーダが無い PC(CPU のエンコーダ)、
  **サービスとして動かすこと**(iivnc-server のものを引き継いだが、iiv では動かしていない)、
  **クリップボードとファイルのコピー＆貼り付け**(同じく引き継いだだけ)、リモート デスクトップの中で動かすこと、2 台の実機の間。

## コマンド ライン

| 引数 | 意味 |
|---|---|
| `-settings` | 設定画面を開く(動いていればそちらで) |
| `-exit` | 動いている iiv-server を終わらせる(終わるまで待つ) |
| `-ini <path>` | 別の設定ファイルで動かす(多重起動の判定も別) |
| `-log` | ログを書く(ini の `log=1` と同じ) |
| `-gdi` | DXGI を使わず GDI で取り込む |
| `-softenc` | GPU のエンコーダを使わない |
| `-testsrc [static\|video]`、`-testfps N`、`-testframes N`、`-testresize N`、`-testdump <bmp>`、`-dryrun` | 検証用(利用者の画面を写さない・入力はログに書くだけ) |

ini だけの項目: `qmove`(動いている間の画質、既定 70)、`qstill`(止まったら送り直す画質、既定 95)、
`stillms`(止まってから送り直すまで、既定 150)、`kbps`(ビットレートの上限。既定 0 = 画質で決める)。
